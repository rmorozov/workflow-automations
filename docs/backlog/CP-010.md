# CP-010 Honest calibration metrics and evidence quality

From the [model review on PR #48](https://github.com/rmorozov/workflow-automations/pull/48#issuecomment-6292432126). Settle the issue; a full forecasting system is not in scope.

`logged_to_predicted` (completed other hours / predicted net hours) relates logged
effort to predicted capacity; it is not estimate accuracy, and 0.8 can mean
under-logging, blocked work, no ready work or omitted duties. Estimate accuracy
needs an estimate baseline and the actual effort for the same scope. The bug share
of logged hours cannot identify focus loss either: "nobody logs focus loss" is an
assumption about time recording. State what is identifiable, expose sample size,
coverage and excluded work per row, and suppress suggested rates when evidence is
below agreed eligibility thresholds (agreed with the teams, not universal). Specify
parent/child deduplication of CompletedWork and how current assignees are treated
against historical contributors.

## Acceptance evidence

Calibration rows carry sample size, coverage and excluded hours; suggestions are
withheld below configurable thresholds with the reason; parent/child work is counted
once; tests include examples where identical logged totals have different
explanations and the output says it cannot tell them apart.
