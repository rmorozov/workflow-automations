# CP-011 Trustworthy calibration history and a backtest

From the [model review on PR #48](https://github.com/rmorozov/workflow-automations/pull/48#issuecomment-6292432126). Settle the issue; a full forecasting system is not in scope.

Cumulative CompletedWork attributed to an item's current iteration moves past effort
when the item moves, and today's roster and assignments distort past capacity.
Decide whether revision-based work deltas (or work logs) and dated roster allocations
are needed, with rules for corrections, transfers and reassignment; fetching
revisions would be a separate ado-triage or ado-graph change. Until then label
snapshot-derived suggestions exploratory. Add a reproducible synthetic backtest that
freezes the inputs available at forecast time and compares the forecast with later
observations, so no future leave, roster or work leaks into it. A real-data pilot
stays local; never commit workplace exports.

## Acceptance evidence

A synthetic backtest fixture with frozen as-of inputs and later observations; a test
proving that leave, roster changes and work after the as-of date do not change the
forecast; suggestions marked exploratory while inputs are snapshot-based; the spec
states the chosen history source and its rules.
