# CP-011 Calibrate on work closed inside the iteration and measure item moves

From the [model review on PR #48](https://github.com/rmorozov/workflow-automations/pull/48#issuecomment-6292432126), narrowed in the thread (Ruslan, 2026-10-20).

Cumulative CompletedWork counted in an item's current iteration misplaces effort
when an item moves. Before building revision-based history (a new ADO fetch in
ado-triage or ado-graph), take the cheap step: optionally count only items whose
`Microsoft.VSTS.Common.ClosedDate` falls inside the iteration's dates, and report
how many completed items closed outside their iteration (a proxy for moves). Decide
on revision deltas and a forecast backtest only if a real calibration run shows
moves are common; a synthetic backtest alone proves the harness, not the model.

## Acceptance evidence

Tests: with the option, an item closed after its iteration's end is excluded and
counted in the moved-items figure; without it, results are unchanged; the spec
records the decision rule for revision-based history.
